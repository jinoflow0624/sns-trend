# 🏨 아콰이어 온라인 (Acquire)

1962년 3M / Avalon Hill판 **아콰이어 클래식 룰**을 그대로 구현한 온라인 보드게임. 2~6인.
**링크만 공유하면 접속**되고, 서버 프로세스가 필요 없어 기존 GitHub Pages에 그대로 얹힌다.

접속 주소: `https://<사용자>.github.io/sns-trend/acquire/`

## 어떻게 서버 없이 동작하나

GitHub Pages는 정적 호스팅이라 WebSocket 서버를 올릴 수 없다. 그래서 **WebRTC P2P(PeerJS)** 구조를 쓴다.

```
방장 브라우저 ←──── WebRTC 직결 ────→ 참가자 브라우저
   (권위 있는 게임 상태 보유)              (상태를 받아 그리기만)
        ↑
   PeerJS 브로커 (최초 연결 중개만, 게임 데이터는 경유하지 않음)
```

- **방장 브라우저가 서버 역할**을 한다. 모든 액션을 검증하고 결과 상태를 각 참가자에게 보낸다.
- 브로커(기본값: PeerJS 공개 서버)는 **최초 연결을 맺어주는 역할만** 하고, 이후 게임 데이터는 P2P로 직접 오간다.
- 각 참가자에게 보내는 상태는 `sanitize()`를 거쳐 **남의 손패와 타일 주머니가 보이지 않는다**.

### 모바일에서 오래 버티기 위한 장치

모바일 브라우저는 탭이 백그라운드로 가거나 화면이 꺼지면 페이지를 얼리고, 메모리가 부족하면 아예 폐기한다.
방장 브라우저가 서버인 구조라 이게 치명적이라서 다음을 넣었다.

- **자동 재연결** — 연결이 끊겨도 내쫓지 않고 지수 백오프(1.5초→10초)로 계속 다시 붙는다.
  백그라운드에서 돌아오면(`visibilitychange`) 즉시 재시도한다.
- **하트비트 감시** — 방장이 5초마다 신호를 보내고, 15초간 소식이 없으면 끊긴 것으로 보고 재연결한다.
  (`close` 이벤트 없이 조용히 죽는 모바일 케이스 대응)
- **화면 꺼짐 방지** — 게임 중 Wake Lock을 잡아 화면이 꺼지지 않게 한다. 화면이 보일 때마다 다시 요청한다.
- **방장 게임 저장** — 방장의 게임 상태가 `localStorage`에 저장되어, 탭이 폐기되거나 새로고침해도
  시작 화면의 **"진행 중이던 방 이어하기"**로 같은 방 코드로 복구된다. 참가자들은 알아서 다시 붙는다.
- **끊긴 동안 입력 잠금** — 호스트에 닿지 않을 입력을 눌러 헛손질하는 일이 없게 액션 패널을 잠근다.
- **로비 유예** — 로비에서 잠깐 끊긴 사람의 자리를 40초간 비워 두고 기다린다.

### 그래도 남는 제약

- **방장이 탭을 닫거나 오래 비우면 그 동안은 게임이 멈춘다.** 방장이 돌아와 페이지를 열면
  (필요하면 "이어하기"를 눌러) 다시 이어진다. 참가자들은 그때까지 재연결을 계속 시도한다.
- 따라서 **방장은 PC 브라우저로 두는 편이 훨씬 안정적이다.** 참가자만 모바일이면 문제가 거의 없다.
- 회사·학교 방화벽이 WebRTC를 막으면 연결되지 않을 수 있다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `engine.js` | 룰 엔진. DOM·네트워크 의존 없는 순수 로직 |
| `room.js` | 방 관리 — `HostRoom`(권위 상태) / `GuestRoom`(미러) / `LocalRoom`(로컬 모드) |
| `net.js` | PeerJS 전송 계층, 방 코드 생성, 재접속 토큰 |
| `app.js` | 화면 렌더링과 입력 처리 |
| `index.html`, `style.css` | 화면 뼈대와 스타일 (라이트/다크 자동) |
| `vendor/peerjs.min.js` | PeerJS 1.5.4 (MIT) 동봉본. CDN이 막혀도 동작하도록 |
| `test/engine.test.mjs` | 룰 엔진 테스트 |

`net.js`의 `keepScreenAwake()`, `room.js`의 하트비트·재연결·상태 저장이 모바일 대응의 핵심이다.

## 테스트

```bash
cd acquire && node test/engine.test.mjs   # 룰 엔진 34개 테스트
```

브라우저 동작 확인은 로컬 모드가 편하다:

```bash
python3 -m http.server 8777    # 저장소 루트에서
# → http://localhost:8777/acquire/?local=4
```

`?local=N` (N=2~6)은 **한 화면에서 전원을 번갈아 조작**하는 모드다. 네트워크 없이 룰을 연습하거나 화면을 점검할 때 쓴다.

## 구현한 룰

클래식 룰을 전부 구현했다.

- 12×9 보드(`1A`~`12I`), 7개 체인(저가 Tower·Luxor / 중가 American·Worldwide·Festival / 고가 Imperial·Continental), 체인당 주식 25장, 초기 자금 $6,000
- 시작 타일 1장씩 뽑아 **`1A`에 가까운 순으로 선공** 결정
- 턴: **타일 1개 배치 → 주식 최대 3장 구매 → 손패 6장으로 보충**
- 창립(**창립 보너스 주식 1장**), 확장, 합병
- 합병: 큰 체인이 흡수, **크기 동률 시 타일 놓은 사람이 생존 체인 선택**, 소멸 체인이 여럿이고 크기가 같으면 **처리 순서도 선택**
- 배당: 대주주 10×주가, 소주주 5×주가. **주주가 1명이면 둘 다 수령**, **대주주 동률이면 대+소를 합쳐 균등 분배($100 올림)**, **소주주 동률이면 소주주 배당만 균등 분배**
- 소멸 주식 처분: **보유 / 매각 / 2장→생존 체인 1장 교환** (생존 체인 재고 한도 내)
- **11칸 이상 = 안전 체인**, 안전 체인 2개를 잇는 타일은 **영구 사용 불가**
- 7개 체인이 모두 보드에 있으면 8번째 창립 타일은 **일시적으로 사용 불가** (체인이 소멸하면 다시 놓을 수 있음)
- 종료: **41칸 이상 체인**이 생기거나 **보드의 모든 체인이 안전**해지면 자기 턴에 **선언 가능(의무 아님)**. 전 체인 배당 + 주식 전량 현금화 후 현금 최다 승리

### 룰과 다른 한 가지 — 자동 타일 교체

영구히 놓을 수 없는(dead) 타일은 **턴이 시작될 때 자동으로 교체**된다.
공식 룰에서는 플레이어의 선택 사항이지만, dead 타일은 어떤 상황에서도 쓸 수 없어 교체가 항상 이득이라 UI를 단순하게 두었다. 교체 내역은 기록 탭에 남는다.

## 자체 브로커 쓰기 (선택)

PeerJS 공개 브로커가 불안정하면 자체 브로커를 지정할 수 있다.

```
/acquire/?peerhost=broker.example.com&peerport=443&peerpath=/myapp
```

`peersecure=0`이면 `ws://`로 붙는다. 이 값들은 초대 링크에도 자동으로 따라간다.
브로커 서버는 [`peer`](https://www.npmjs.com/package/peer) 패키지로 띄울 수 있다.
