# 구글 플레이 출시 순서 (개발자 등록 → 정식 출시)

작성일 2026-10-05. 구글 정책은 자주 바뀌니 각 단계에서 Play Console 화면 안내를 우선하세요.
기술 절차(빌드·서명·assetlinks)는 `../README-배포.md` 4번에 있습니다.

## 0단계: 시작 전에 정할 것

| 결정 | 선택지 | 추천 |
|---|---|---|
| 계정 종류 | **개인** (신분증만 있으면 됨) / **조직** (사업자등록 + D-U-N-S 번호 필요) | 사업자가 없으면 개인. **조직 계정은 "테스터 12명 × 14일" 규칙이 없어서**, 사업자등록이 이미 있으면 조직이 더 빠를 수 있음 |
| 게임 이름 | 요트 히어로즈 (지금 main에 반영됨) / 다이스 크라운 길드 등 | 스토어 앱 이름은 나중에도 바꿀 수 있음. **패키지 이름 `com.hahahoho.diceheroes` 는 영영 못 바꿈** |
| 구글 계정 | 개인 Gmail / 게임 전용 새 Gmail | **게임 전용 Gmail을 새로 만들기** (Firebase·애드몹·SNS를 한 계정으로 모으기 좋음, 나중에 넘기기도 쉬움) |

## (사업자등록이 있을 때) 조직 계정으로 가기 — 추천 경로
조직 계정은 **비공개 테스트 12명 × 14일 규칙이 적용되지 않아** 출시가 2~3주 빨라집니다. 개인사업자도 가능합니다.

1. **영문 사업자등록증명** 발급 (홈택스 → 증명서 발급 → 사업자등록증명, 영문 선택)
2. **D-U-N-S 번호** 받기 (무료)
   - 애플 D-U-N-S 조회 페이지(https://developer.apple.com/enroll/duns-lookup/)에서 검색 → 없으면 신청
   - 영문 상호·주소는 영문 증명서와 **글자 하나까지 똑같이** 입력
   - 발급까지 영업일 최대 5일 + 반영 며칠 (넉넉히 1~3주)
   - 국내 대행처 나이스디앤비(nicednb.com)도 있지만 유료 서비스가 섞여 있으니 무료 경로를 먼저 시도
3. Play Console 가입에서 **조직** 선택 → D-U-N-S 번호, 조직 이름·주소·전화·웹사이트 입력
   - 이름·주소가 D&B 기록과 같아야 인증이 빨리 끝남
4. 조직 인증 서류 제출 (사업자등록증 등), 연락처·기기 인증은 개인과 같음
5. 그 뒤는 2단계(앱 만들기)부터 같고, **4단계(12명 테스트)는 건너뛰고** 내부 테스트로 확인한 뒤 바로 프로덕션 출시 가능
   - 그래도 내부/비공개 테스트로 지인 몇 명에게 먼저 돌려 보는 건 권장

주의
- 조직 계정은 **조직 주소·전화가 스토어에 공개**될 수 있습니다. 사업장 주소가 집이라면 확인 필요
- 개발자 이름은 상호(예: HAHAHOHO COMPANY)로 표시. 상호가 다르면 D-U-N-S 상호 기준
- 인앱 판매 시 통신판매업 신고·부가세 등은 세무사/관할 구청에 확인

## 1단계: 개발자 계정 등록 (개인 계정일 때) (1~7일)
1. https://play.google.com/console 접속 → 게임 전용 구글 계정으로 로그인
2. **개인** 선택 → 정보 입력
   - 개발자 이름 (스토어에 공개): `HAHAHOHO COMPANY`
   - 법적 이름·주소: 신분증과 똑같이
   - 연락처 이메일·전화번호 (구글 연락용), 개발자 이메일 (스토어에 공개 → 문의용 주소 권장)
3. 등록비 **$25 (1회)** 해외 결제 카드로 결제
4. **신원 인증**: 신분증(주민등록증·운전면허증·여권) 사진 업로드, 필요하면 주소 증빙. 보통 며칠 걸림
5. 이메일·전화번호 인증 (인증번호 입력)
6. **기기 인증**: 안드로이드 10 이상 실제 폰에 "Google Play Console" 앱 설치 → 같은 계정으로 로그인 → 안내대로 인증
   - 이 단계를 안 하면 앱 게시가 막힙니다
7. (판매·결제를 붙일 거라면) **결제 프로필(판매자 계정)** 만들기
   - 인앱 구매 수익을 받을 은행 계좌·세금 정보
   - 판매자 정보가 스토어에 공개될 수 있으니 화면 안내를 확인

## 2단계: 앱 만들기 + 첫 빌드 (1~2일, 개발 세션과 함께)
1. Play Console → **앱 만들기**
   - 앱 이름, 기본 언어 한국어, **게임**, **무료** 선택
   - 무료로 올린 앱은 나중에 유료로 바꿀 수 없음. 인앱 구매는 가능
2. 내 컴퓨터에서 `README-배포.md` 4번대로 `bubblewrap build` → `.aab` 파일 생성
   - ⚠️ **서명 키(`android.keystore`)와 비밀번호를 잃어버리면 업데이트를 못 합니다**
   - 클라우드 드라이브와 USB 두 곳에 백업하세요. 저장소에는 절대 올리지 마세요
3. **테스트 → 내부 테스트** 트랙에 `.aab` 업로드 → **Play 앱 서명** 사용 동의
4. **앱 무결성 → 앱 서명**의 SHA-256 지문을 `twa/assetlinks.json` 에 넣고 웹 재배포
   - 이걸 해야 앱 위에 주소창이 안 보입니다
   - 개발 세션에 부탁해도 됩니다
5. 내 폰에 내부 테스트로 설치해서 확인
   - 전체 화면, 온라인 방 초대 링크가 앱으로 열리는지, 흔들기·소리

## 3단계: 스토어 등록 정보 + 앱 콘텐츠 (1~2일)
대시보드의 "앱 설정" 체크리스트를 위에서부터 채웁니다.

- **기본 스토어 등록정보**: 앱 이름(30자), 짧은 설명(80자), 자세한 설명(4000자), 아이콘 512×512, 그래픽 이미지 1024×500, 폰 스크린샷 2장 이상(4~8장 권장)
  - 이 자료는 마케팅 세션이 `02-스토어-등록정보.md`, `03-스토어-그래픽/` 으로 준비
- **개인정보처리방침 URL**: `https://diceheroes-4fbbb.web.app/privacy.html`
  - 문의 이메일이 채워져 있는지 확인
- **앱 액세스 권한**: "모든 기능을 제한 없이 사용 가능" (로그인 없음)
- **광고**: 광고 세션이 광고를 넣으면 **"예, 광고 포함"**. 지금 없으면 "아니요", 넣을 때 바꾸기
- **콘텐츠 등급(IARC) 설문**
  - 폭력: 도트 캐릭터의 판타지 공격 연출 정도
  - 도박: **실제 돈 도박 없음**. 단, "도박사" 직업과 주사위는 게임 요소라고 정확히 답하기
  - 사용자 간 상호작용: 온라인 방(채팅이 없다면 "없음")
- **타겟층**: 13세 이상 권장 (어린이 대상으로 고르면 정책이 훨씬 까다로움)
- **데이터 보안 양식**: `README-배포.md` 4-7번 문구대로 (익명 ID, 동의 시 분석)
- **카테고리**: 게임 → **보드** (또는 롤플레잉). 태그: 주사위, 보드게임, 멀티플레이어, 픽셀 등
- **연락처**: 이메일 필수, 웹사이트 선택

## 4단계: 비공개 테스트 12명 × 14일 (최소 14일, 실제론 3주 잡기)
자세한 모집 문구·안내문은 `01-비공개테스트-모집.md`.

1. **테스트 → 비공개 테스트 → 트랙 만들기** → 내부 테스트의 빌드를 이 트랙으로 승격
2. 테스터 등록: **구글 그룹** 하나 만들어 등록하는 걸 추천 (테스터가 그룹에 가입만 하면 됨)
3. **국가 선택** (대한민국 + 테스터가 있는 나라), 검토 제출
   - 첫 검토는 며칠 걸릴 수 있음
4. 검토 통과 → **참여 링크** 복사 → 테스터에게 안내문과 함께 전송
5. **옵트인 12명이 된 날부터 14일 연속**
   - 중간에 12명 아래로 떨어지면 다시 셀 수 있으니 15~20명 확보
6. 기간 중 할 일
   - 테스터 의견을 **날짜별로 기록**
   - **업데이트 1~2번** 올리기 (의견 반영 증거)
   - 테스터에게 실제로 플레이를 부탁하기 (참여도도 봄)

## 5단계: 프로덕션 액세스 신청 (검토 약 7일 이내)
대시보드 → **프로덕션 액세스 신청** → 질문 약 10개 (서술형 + 선택형). 미리 답을 준비하세요.

- 테스터를 어떻게 모았나 → "지인·보드게임 커뮤니티에서 모집한 N명"
- 테스터가 얼마나 사용했나 / 어떤 기능을 써 봤나 → 설문 결과 (튜토리얼·봇 대전·협동 보스·온라인 방)
- 받은 의견과 **고친 것** → 의견 기록에서 3~5개 구체적으로 (예: "튜토리얼 3단계가 헷갈린다 → 문구 수정, v1.0.2")
- 앱의 대상과 가치 → "요트 주사위 규칙을 아는 사람, 친구와 짧게 즐길 보드게임을 찾는 사람"
- 출시 준비가 됐다고 보는 이유 → 크래시 없음, 테스트 기간 업데이트 내역

> 거절되면 "테스트를 더 하라"는 답이 옵니다. 테스트를 이어 가며 의견·업데이트를 더 쌓은 뒤 다시 신청하면 됩니다.

## 6단계: 정식 출시
1. **프로덕션** 트랙에 빌드 승격 → 국가 선택 → **단계적 출시**(예: 20% → 50% → 100%) 추천
2. 출시 직후 **Android vitals**(비정상 종료·ANR) 확인, 리뷰에 답글 달기
3. 마케팅 출시 계획(`04-출시-마케팅-계획.md`)대로 홍보 시작
